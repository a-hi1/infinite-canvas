# 云端账号与历史

云端账号是**可选增强**：未登录时本地画布、工作台、素材、提示词库仍完整可用。登录后，图片/视频工作台会在本地生成成功后，异步把结果同步到服务器历史。

## 组成

| 路径 | 说明 |
| --- | --- |
| `api/` | Node 22 业务 API：注册登录、jobs 上云、鉴权读文件 |
| `docker-compose.local.yml` | `app` + `api` + `ai-proxy` |
| `nginx.conf` | 同源转发 `/api/` 与 `/ai-proxy/` |
| `.env.api.example` | API 环境变量示例 |

数据默认落在宿主机 `./data/api`（容器内 `/data`），包含 JSON 库与 `uploads/`。

## 本地开发

1. 启动 API（示例）：

```bash
cd api
# Windows / Linux 均可
DATA_DIR=../data/api PORT=8080 node src/index.js
```

2. 前端 `web`：

```bash
cd web
bun install
bun run dev
```

Windows 本机开发推荐（避开 VS Code 抢占 `127.0.0.1:3001`/`8080`）：

```bash
docker compose -f docker-compose.local.yml -f docker-compose.dev-host.yml up -d
cd web && bun run dev
# 浏览器：http://localhost:3000
# Vite 默认把 /api、/ai-proxy 转到 http://127.0.0.1:3011（dev-host 映射）
```

也可用仅 `docker-compose.local.yml`（站点 `3001`），此时设置 `VITE_DEV_PROXY_TARGET=http://127.0.0.1:3001`。  
浏览器只访问同源 `/api/*`，Cookie 可带上。本机上云数据在**本机** `./data/api`，与服务器磁盘无关。

## Docker 源码部署

```bash
# 可选：复制并编辑
cp .env.api.example .env.api

sudo docker compose -f docker-compose.local.yml up -d --build
```

- 站点：`http://服务器:3001`
- API 默认**不**映射宿主机端口，只在 Docker 网络内 `api:8080`，由 Nginx 同源 `/api/` 转发（避免抢占服务器 8080）
- 本机排查直连 API：可在 `docker-compose.local.yml` 临时打开 `8081:8080`

### 推荐环境变量

见 `.env.api.example`。Compose 从仓库根目录 **`.env`** 做变量插值（可 `cp .env.api.example .env` 后修改；**不要提交真实 `.env`**）。

| 变量 | 含义 |
| --- | --- |
| `API_INVITE_CODE` | 非空则注册必须邀请码（防刷盘） |
| `API_COOKIE_SECURE` | **公网 HTTPS 必须 `true`** |
| `API_ALLOWED_ORIGINS` | 允许带 Cookie 的前端 Origin 白名单（**不要写 `*`**） |
| `API_TRUST_PROXY_SAME_ORIGIN` | 默认 `true`：浏览器同源经 Nginx 访问时，若 `Origin` 与 `Host`/`X-Forwarded-Host`+协议一致则放行（适合 `http://公网IP:3001`）；跨站仍只靠白名单。仅白名单模式可设 `false`。Nginx 必须转发 `$http_host`（保留端口）与 `X-Forwarded-Host`，不要只用会丢端口的 `$host`，否则 `http://IP:3001` 会被算成 `http://IP` 导致登录 403 |
| `API_MAX_USER_BYTES` | 单用户云端容量上限 |
| `API_MAX_IMAGE_BYTES` / `API_MAX_VIDEO_BYTES` | 单文件上限 |
| `API_REMOTE_FETCH_TIMEOUT_MS` | 服务端拉取远程媒体超时（视频默认约 90s） |
| `API_REMOTE_FETCH_MAX_REDIRECTS` | 远程拉取最大重定向次数（默认 3） |
| `API_ADMIN_TOKEN` | 可选。非空时允许 `POST /api/admin/credits/grant` 手工加额（Header：`X-Admin-Token` 或 `Authorization: Bearer`）；空则该接口 503。**勿提交真实令牌** |

### 积分账本（P1.0-C）

- 存储：`data/api/db.json` 的 `credit_ledger`（只追加）+ 用户字段 `credit_balance_cents`（缓存）
- 单位：整数分（`cny_cents`），避免浮点
- 用户：`GET /api/auth/me` 的 `credits.balance_cents`；`GET /api/credits/ledger` 查自己流水
- 管理员手工加额（运维，非前端入口）：

```bash
curl -sS -X POST http://127.0.0.1:3011/api/admin/credits/grant \
  -H "Content-Type: application/json" \
  -H "X-Admin-Token: $API_ADMIN_TOKEN" \
  -d '{"email":"user@example.com","amount_yuan":10,"note":"试用赠送","idempotency_key":"trial-2026-07-17-user"}'
```

### 平台图片代生成（P1.0-D，可选）

默认关闭。开启后登录用户可在**图片工作台**打开「平台积分生图」，走服务端 Key，浏览器不暴露上游密钥。

| 变量 | 含义 |
| --- | --- |
| `API_PLATFORM_IMAGE_ENABLED` | `true` 才开放网关 |
| `API_PLATFORM_IMAGE_BASE_URL` | OpenAI 兼容上游 Base URL（可与 ai-proxy 上游相同中转） |
| `API_PLATFORM_IMAGE_API_KEY` | 仅服务端使用的上游 Key，**勿写进前端** |
| `API_PLATFORM_IMAGE_MODEL` | 允许的平台模型名（默认 `gpt-image-2`） |
| `API_PLATFORM_IMAGE_PRICE_CENTS` | 成功一张扣多少分（10=¥0.10；0=不扣费） |

- 接口：`POST /api/generate/image`（需登录 Cookie）
- 幂等：`client_local_id` 重复提交返回已有 job，不双扣
- 文生图：无 `images` 时调上游 `/images/generations`
- 图生图：`images: [{ "data_url": "data:image/png;base64,..." }]`（最多 4 张）时调上游 `/images/edits`
- 画布默认路径仍是用户自己的渠道；支付入账可后置

### 平台视频代生成（P1.0-F，可选，仅文生视频）

| 变量 | 含义 |
| --- | --- |
| `API_PLATFORM_VIDEO_ENABLED` | `true` 才开放视频网关 |
| `API_PLATFORM_VIDEO_BASE_URL` | OpenAI 兼容上游；空则回落 `API_PLATFORM_IMAGE_BASE_URL` |
| `API_PLATFORM_VIDEO_API_KEY` | 服务端 Key；空则回落图片上游 Key |
| `API_PLATFORM_VIDEO_MODEL` | 允许的视频模型名（默认 `sora-2`） |
| `API_PLATFORM_VIDEO_PRICE_CENTS` | 成功一条扣多少分（默认 50） |

- 接口：`POST /api/generate/video`（需登录）
- 仅文生视频；参考图/视频/音频请继续用 BYOK（Grok/Seedance 等）
- 幂等与扣费语义同图片网关
- 运维探活：`GET /api/health` 的 `platform.image_enabled` / `platform.video_enabled`（不含密钥）

### 画布项目云同步（P2.0-A）

- 接口（需登录）：`GET /api/projects`、`GET/PUT/DELETE /api/projects/:id`
- 存储：元数据在 `db.json` 的 `projects`；正文 JSON 在 `data/api/projects/{userId}/{id}.json`
- 策略：**本地优先**；登录后浏览器防抖推送；云端更新冲突返回 409（可 `?force=1` 覆盖）
- **范围：** 项目 JSON + 节点引用的本地 `storageKey` 媒体（`POST /api/blobs`，按 `client_key` 幂等；`GET /api/blobs/by-key/:key`）
- 远程仅 URL、无本地 blob 的媒体不会上传（与 CORS/临时链一致）
- 与 WebDAV `app-sync` 并存：WebDAV 仍是可选整包同步；本接口是账号维度的项目/媒体同步

### 素材库云同步（P2.0-C）

- 接口（需登录）：`GET /api/assets`、`PUT /api/assets`（可选 `?force=1`）
- 存储：元数据在 `db.json` 的 `asset_manifests`；清单 JSON 在 `data/api/assets/{userId}/manifest.json`
- 清单字段：`assets[]` + `tombstones[]`（删除墓碑，防止另一设备把已删素材复活）
- 策略：本地优先；登录后素材页自动拉一次，并支持「同步云端」；增删改防抖推送；云失败不丢本机
- 媒体：复用 `POST /api/blobs` / `GET /api/blobs/by-key/:key`（与画布同一套幂等 key）
- 冲突：云端 `updatedAt` 更新时返回 409 `sync_conflict`；前端合并后可 force 回写

### 访问地址与登录 403

浏览器打开 `http://服务器IP:3001` 时，登录请求会带 `Origin: http://服务器IP:3001`。  
默认开启 `API_TRUST_PROXY_SAME_ORIGIN=true` 后，经同源 Nginx `/api/` 转发时会把该 Origin 与请求 Host 对齐放行，**不必**再为每个 IP 手写白名单。  
若关闭该开关，或使用真正的跨站前端域名，仍须把完整 Origin 写入 `API_ALLOWED_ORIGINS`。

公网域名反代到 `127.0.0.1:3001` 时：

1. 全站 HTTPS  
2. 根目录 `.env` 设 `API_COOKIE_SECURE=true`  
3. `API_ALLOWED_ORIGINS` 写上真实前端源，例如 `https://canvas.example.com`（跨站时必填）  
4. 开放注册务必设 `API_INVITE_CODE`  
5. 重建 api 容器使环境变量生效  

远程上云 `from-url` 仅允许 https 白名单媒体域名，并在 DNS 解析后拒绝内网地址；这是后续服务端代生成前的 SSRF 底线，不要为了“方便”放开任意 URL。

## 备份与恢复

### 备份

Linux / 服务器：

```bash
chmod +x scripts/backup-api-data.sh
./scripts/backup-api-data.sh
# 产物默认：backups/api/api-data-时间戳.tar.gz
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup-api-data.ps1
```

建议：每日 cron / 计划任务跑一次；备份目录勿提交 Git（`data/` 已忽略，`backups/` 也建议忽略）。

### 恢复（示意）

```bash
# 先停 api
sudo docker compose -f docker-compose.local.yml stop api

# 解压覆盖 data/api（按你的备份路径调整）
tar -xzf backups/api/api-data-YYYYMMDD-HHMMSS.tar.gz -C ./data

sudo docker compose -f docker-compose.local.yml start api
```

恢复前请确认没有把错误备份盖到生产数据上。

## 双轨原则

| 场景 | 行为 |
| --- | --- |
| 未登录 | 仅本地；生成记录标「仅本机」 |
| 已登录 | 本地成功后异步上云；失败可重试，不改写本地成功 |
| API 挂了 | 本地创作不受影响 |
| 清浏览器数据 | 重登后云端历史仍可看 |

后续扩展（服务端代生成、画布同步、计费）应继续遵守：本地 store 不删，只加 cloud adapter；云资源一律带 `user_id`。

## 本机 dev 与服务器（勿混）

| | 本机开发 | 服务器部署 |
| --- | --- | --- |
| 用户入口 | `http://localhost:3000` | `http://IP:3001` 或 HTTPS 域名 |
| 数据目录 | 本机 `./data/api` | 服务器 `./data/api` |
| 可选 HTTP_PROXY | 可指向本机 Clash（如 `host.docker.internal:7897`） | **默认不要**抄本机代理端口 |
| 端口 3011 | 仅 dev-host 给 Vite 用 | 访客不需要 |

健康检查：

```bash
./scripts/check-cloud-stack.sh
# Windows: scripts/check-cloud-stack.ps1
```

`/api/health` 现在除 `ok` 外，还会返回 `allowedOriginCount`、`trustProxySameOrigin`、`envProxy` 等字段，便于确认当前是“仅白名单”还是“同源放行 + 容器代理出网”模式。  
`/ai-proxy/health` 会返回 `upstreamConfigured`、`authRequired`、`envProxy`、`timeoutMs`，便于排查是上游未配、访问令牌还是容器出网问题。  
更新了这部分代码后，记得重建对应容器再看 health 返回值：

```bash
docker compose -f docker-compose.local.yml up -d --build api ai-proxy
```

完整出门条件见 [P0.5c 验稳收口](/docs/progress/p05c-acceptance)。

## Grok / vidgen 说明

中转站生成成功后，结果常是 `https://vidgen.x.ai/...` 临时链。

- **生成**走中转站，不依赖本机/服务器能否打开 vidgen  
- **代理预览 / media 落盘 / from-url 上云**依赖运行 `ai-proxy`/`api` 的环境访问该 CDN  
- 浏览器开系统代理 ≠ Docker 容器自动出网；容器需单独 `HTTP_PROXY` 或机房直连  
- 已有本地 `storageKey`/blob 的上云不依赖再次访问 vidgen  

## 错误 reason code（前后端稳定契约）

云端 API 现在会在错误 envelope 里附带 `reason` 字段，前端应优先使用它做行为判断，不再长期依赖中文文案匹配。

当前已落地的代表性 reason：

| reason | 场景 |
| --- | --- |
| `auth_required` | 受保护接口未登录 |
| `origin_not_allowed` | Origin / Host 同源校验失败 |
| `storage_quota_exceeded` | 单用户云端容量不足 |
| `invite_code_invalid` | 注册邀请码无效 |
| `email_already_registered` | 注册邮箱已存在 |
| `login_invalid_credentials` | 登录邮箱或密码错误 |
| `account_temporarily_locked` | 登录失败过多暂时锁定 |
| `upload_rate_limited` | 上传过于频繁 |
| `login_rate_limited` / `register_rate_limited` | 登录/注册频率限制 |

后续 P1/P2 新错误应继续沿用：**HTTP 状态 + 稳定 reason + 用户可读 msg**。

## 安全注意

- 不要提交真实 `.env` / `.env.api` / `.env.proxy`  
- 开放注册务必设邀请码或后续邮箱验证  
- 文件接口必须登录且校验归属（已实现）  
- 以后平台上游 Key 只放服务端，不下发浏览器  
- `API_ALLOWED_ORIGINS` 禁止 `*`；`from-url` 保持 SSRF 白名单
