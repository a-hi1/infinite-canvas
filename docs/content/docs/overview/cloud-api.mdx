# 云端账号与历史

云端账号是**可选增强**：未登录时本地画布、工作台、素材、提示词库仍完整可用。登录后，图片/视频工作台会在本地生成成功后，异步把结果同步到服务器历史。

## 组成

| 路径 | 说明 |
| --- | --- |
| `api/` | Node 22 业务 API：注册登录、jobs 上云、鉴权读文件 |
| `docker-compose.local.yml` | `app` + `api` + `ai-proxy` |
| `nginx.conf` | 同源转发 `/api/` 与 `/ai-proxy/` |
| `.env.api.example` | API 环境变量示例 |

数据默认落在宿主机 `./data/api`（容器内 `/data`），包含 JSON 库与 `uploads/`。

## 本地开发

1. 启动 API（示例）：

```bash
cd api
# Windows / Linux 均可
DATA_DIR=../data/api PORT=8080 node src/index.js
```

2. 前端 `web`：

```bash
cd web
bun install
bun run dev
```

Vite 将 `/api` 代理到 `http://127.0.0.1:8080`。浏览器只访问同源 `/api/*`，Cookie 可带上。

## Docker 源码部署

```bash
# 可选：复制并编辑
cp .env.api.example .env.api

sudo docker compose -f docker-compose.local.yml up -d --build
```

- 站点：`http://服务器:3001`
- API 默认**不**映射宿主机端口，只在 Docker 网络内 `api:8080`，由 Nginx 同源 `/api/` 转发（避免抢占服务器 8080）
- 本机排查直连 API：可在 `docker-compose.local.yml` 临时打开 `8081:8080`

### 推荐环境变量

见 `.env.api.example`。Compose 从仓库根目录 **`.env`** 做变量插值（可 `cp .env.api.example .env` 后修改；**不要提交真实 `.env`**）。

| 变量 | 含义 |
| --- | --- |
| `API_INVITE_CODE` | 非空则注册必须邀请码（防刷盘） |
| `API_COOKIE_SECURE` | **公网 HTTPS 必须 `true`** |
| `API_ALLOWED_ORIGINS` | 允许带 Cookie 的前端 Origin 白名单（**不要写 `*`**） |
| `API_TRUST_PROXY_SAME_ORIGIN` | 默认 `true`：浏览器同源经 Nginx 访问时，若 `Origin` 与 `Host`/`X-Forwarded-Host`+协议一致则放行（适合 `http://公网IP:3001`）；跨站仍只靠白名单。仅白名单模式可设 `false` |
| `API_MAX_USER_BYTES` | 单用户云端容量上限 |
| `API_MAX_IMAGE_BYTES` / `API_MAX_VIDEO_BYTES` | 单文件上限 |
| `API_REMOTE_FETCH_TIMEOUT_MS` | 服务端拉取远程媒体超时（视频默认约 90s） |
| `API_REMOTE_FETCH_MAX_REDIRECTS` | 远程拉取最大重定向次数（默认 3） |

### 访问地址与登录 403

浏览器打开 `http://服务器IP:3001` 时，登录请求会带 `Origin: http://服务器IP:3001`。  
默认开启 `API_TRUST_PROXY_SAME_ORIGIN=true` 后，经同源 Nginx `/api/` 转发时会把该 Origin 与请求 Host 对齐放行，**不必**再为每个 IP 手写白名单。  
若关闭该开关，或使用真正的跨站前端域名，仍须把完整 Origin 写入 `API_ALLOWED_ORIGINS`。

公网域名反代到 `127.0.0.1:3001` 时：

1. 全站 HTTPS  
2. 根目录 `.env` 设 `API_COOKIE_SECURE=true`  
3. `API_ALLOWED_ORIGINS` 写上真实前端源，例如 `https://canvas.example.com`（跨站时必填）  
4. 开放注册务必设 `API_INVITE_CODE`  
5. 重建 api 容器使环境变量生效  

远程上云 `from-url` 仅允许 https 白名单媒体域名，并在 DNS 解析后拒绝内网地址；这是后续服务端代生成前的 SSRF 底线，不要为了“方便”放开任意 URL。

## 备份与恢复

### 备份

Linux / 服务器：

```bash
chmod +x scripts/backup-api-data.sh
./scripts/backup-api-data.sh
# 产物默认：backups/api/api-data-时间戳.tar.gz
```

Windows：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\backup-api-data.ps1
```

建议：每日 cron / 计划任务跑一次；备份目录勿提交 Git（`data/` 已忽略，`backups/` 也建议忽略）。

### 恢复（示意）

```bash
# 先停 api
sudo docker compose -f docker-compose.local.yml stop api

# 解压覆盖 data/api（按你的备份路径调整）
tar -xzf backups/api/api-data-YYYYMMDD-HHMMSS.tar.gz -C ./data

sudo docker compose -f docker-compose.local.yml start api
```

恢复前请确认没有把错误备份盖到生产数据上。

## 双轨原则

| 场景 | 行为 |
| --- | --- |
| 未登录 | 仅本地；生成记录标「仅本机」 |
| 已登录 | 本地成功后异步上云；失败可重试，不改写本地成功 |
| API 挂了 | 本地创作不受影响 |
| 清浏览器数据 | 重登后云端历史仍可看 |

后续扩展（服务端代生成、画布同步、计费）应继续遵守：本地 store 不删，只加 cloud adapter；云资源一律带 `user_id`。

## 安全注意

- 不要提交真实 `.env.api`  
- 开放注册务必设邀请码或后续邮箱验证  
- 文件接口必须登录且校验归属（已实现）  
- 以后平台上游 Key 只放服务端，不下发浏览器
