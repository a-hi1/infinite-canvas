# P0.5c 验稳收口

本阶段**不新开计费、不做画布全量同步**。目标是把已上线的「本地默认 + 可选云历史」收成可重复验收、可运维的基线。

代码基线参考：`main` 上云端相关提交（含同源登录、不占宿主机 8080、视频 media 回退、可选容器 `HTTP_PROXY` 等）。

## 原则（验收时不得破坏）

| 原则 | 含义 |
| --- | --- |
| 本地默认轨 | 未登录可用；配置/画布/素材/本机历史在浏览器 |
| 云可降级 | 上云失败不改写本地成功 |
| 登录仍 BYOK | 默认不改变生成路径；平台额度以后须显式开关 |
| 环境隔离 | 本机 `data/api` 与服务器 `data/api` 互不影响 |
| 浏览器代理 ≠ 容器出网 | 系统/Clash 代理不会自动进 Docker |

## 快速健康检查

服务器 / Linux：

```bash
chmod +x scripts/check-cloud-stack.sh
./scripts/check-cloud-stack.sh
# BASE_URL=http://127.0.0.1:3001 ./scripts/check-cloud-stack.sh
```

本机 Windows（dev-host 默认站点常为 3011）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check-cloud-stack.ps1
# 或指定：
# powershell -ExecutionPolicy Bypass -File .\scripts\check-cloud-stack.ps1 -BaseUrl http://127.0.0.1:3011
```

## A. 双轨回归（发版门禁）

- [ ] **停掉 api 容器**后，未登录仍可：生图 / 画布 / 素材 / 提示词库
- [ ] 登录后生图：本机成功；在出网允许时云端列表可见、可预览
- [ ] 上云失败时本机记录仍为成功，可「重试上云」
- [ ] 用户 B 无法读取用户 A 的 `/api/files/:id`
- [ ] 同一结果连续「重试上云」不重复占盘（`deduped`）
- [ ] 账号弹层可见容量/条数；401 只清一次会话

## B. 环境分册

### B1. 本机开发

- [ ] `docker compose -f docker-compose.local.yml -f docker-compose.dev-host.yml up -d`
- [ ] 前端 `web` dev：`http://localhost:3000`（Vite 将 `/api`、`/ai-proxy` 转到 `3011`）
- [ ] 登录不再出现误打到占用 8080 的其它服务导致的 `501`
- [ ] 本机上云写入的是**本机** `./data/api`，不是服务器磁盘
- [ ] 若使用 Clash 等：仅本机 `.env` 配置 `HTTP_PROXY`（**勿提交、勿照搬服务器**）

### B2. 服务器部署

- [ ] `git pull` 到目标提交后 `docker compose -f docker-compose.local.yml up -d --build`
- [ ] 用户入口统一为 `http://服务器:3001`（或 HTTPS 域名），**无 3011 要求**
- [ ] 根目录 `.env` **没有**本机 `7897/7890` 之类开发代理（除非服务器故意走代理）
- [ ] `./scripts/check-cloud-stack.sh` 硬失败为 0
- [ ] 公网 HTTPS：`API_COOKIE_SECURE=true`，白名单/同源策略正确
- [ ] 备份：`./scripts/backup-api-data.sh` 能产出压缩包

## C. Grok / vidgen 预期（不要当回归 bug）

| 现象 | 含义 |
| --- | --- |
| 中转站生成成功，有 `vidgen.x.ai` URL | 生成链路 OK |
| `/ai-proxy/media` 或 `from-url` 502 | **运行环境出网**拉不到 CDN，不是登录坏了 |
| 代理失败后预览回退原始 URL | 预期行为；浏览器能否播取决于访客网络 |
| 已有本地 `storageKey`/blob 再上云 | 不依赖再次访问 vidgen |

可选探测：

```bash
sudo docker compose -f docker-compose.local.yml exec ai-proxy \
  wget -S -O /dev/null --timeout=20 https://vidgen.x.ai/ 2>&1 | head -20
```

## E. 自动化已覆盖 vs 仍须人工

| 类别 | 状态 | 说明 |
| --- | --- | --- |
| `check-cloud-stack.*` | 可重复自动 | compose 三服务、页面、`/api/health`、`/ai-proxy/health`、platform 默认关、env 代理卫生 |
| `smoke-dual-track.*` | 可重复自动 | 停 `api` 后页面仍 200，`/api` 失败/502，再启回 health |
| A 中 UI 双轨（登录上云、幂等点两次、跨用户、401 只清一次） | **仍须人工** | 依赖真实账号与浏览器 |
| B2 服务器分册 | **仍须人工** | 目标机 `git pull` + compose + 备份 + HTTPS |
| C vidgen 出网 | 半自动 | 脚本 WARN 即可；勿当登录 bug |
| 平台扣积分 / 支付 | **后置** | 网关代码可在、默认关；不作为 P0.5c 出门条件 |

## F. P0.5c 出门条件 → 才能扩大收费面 / P2

同时满足：

1. A 双轨门禁通过（自动 smoke + 人工 UI 勾选项）  
2. B2 服务器检查通过（若该环境要给他人用）  
3. C 类限制已写进运维认知（本清单 / `cloud-api`）  
4. 无未关闭的 P0 级正确性缺陷  

通过后路线选择：

| 目标 | 下一期 |
| --- | --- |
| 本地体验 / 上游切片 | 组节点、模型脚本等（见 [上游跟进矩阵](/docs/progress/upstream-follow)） |
| 控成本 / 藏平台 Key / 额度 | 再开 `API_PLATFORM_*` + **支付入账**（后置；默认 BYOK） |
| 多设备创作 | **P2 MVP**：项目列表/打开/保存 JSON，先本地后异步推云 |

**禁止：** 跳过本清单直接支付；一次合并完整视频计费 + 全量素材库；大重构画布/AI 客户端；整仓 merge 上游。

## 设计锚点（做下一步时仍要遵守）

- job.`source`：`client_upload` / `server_fetch` / 预留 `server_generate`
- 幂等键语义统一：`client_local_id`
- 文件走 `files` + `storage_backend`
- 云资源带 `user_id`（预留 `org_id`）
- 前端只依赖 `/api/*` 契约；本地 store 不删
