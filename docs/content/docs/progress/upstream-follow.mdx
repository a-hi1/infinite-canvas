# 上游跟进矩阵

本文档给后续开发/新会话用：**只读跟踪上游，按切片移植**。  
**不是**版本号对齐清单；本 fork 主线仍是本地 BYOK + 可选云历史 + `ai-proxy`。

## 对照基线（写文档时）

| 项 | 值 |
| --- | --- |
| 自用 remote | `a-hi1` → `https://github.com/a-hi1/infinite-canvas.git` |
| 上游 remote | `origin` → `basketikun/infinite-canvas`（只 fetch，默认不 push） |
| 分叉点 | 约 `568f0f1`（2026-07-05） |
| 本 fork tip（参考） | `main` / `a-hi1/main`（含图生图边界 S1） |
| 上游 tip（参考） | `origin/main` **`v0.10.0`**（2026-07-25）；勿整包对齐版本号 |
| 禁止 | 整仓 `merge`/`rebase` 上游；用上游 `docker-compose`/`nginx`/`Dockerfile` 覆盖本仓库端口与 `/api` `/ai-proxy` |

核对命令：

```bash
git fetch origin --tags --prune
git merge-base HEAD origin/main
git rev-list --left-right --count HEAD...origin/main
git log --oneline HEAD..origin/main | head
```

## 硬规则

1. 推送：`git push a-hi1 main`（不要默认 `origin`）。
2. 部署心脏锁定：`3001:3000`、dev-host `3011`、`nginx` 的 `/api/` `/ai-proxy/`、`$http_host` 保留端口。
3. 一次一事：一个移植分支只带一个能力切片；合入前跑 `scripts/check-cloud-stack.*` + 双轨冒烟。
4. 安全：远程插件/自定义脚本默认按「不可信代码」评估；平台扣积分与支付产品面后置。
5. 文档：切片完成后更新本表「状态」列，并写 `pending-test.mdx`；勿只改代码不改矩阵。

## 推荐移植顺序（减少返工）

```text
1. 本地 BYOK 体验小切片（透明背景 ✅ → 组节点 ✅ → 上游单文件 bugfix）
2. 中转兼容长期解（模型调用脚本 ✅ 最小切片；旧特判只维护不扩张）
3. 插件系统（独立分支 + 安全白名单；勿与计费/云同步并行大改）
4. 收费产品（开 API_PLATFORM_* + 支付入账）— 明确后置
5. Postgres / S3 — 与插件大改错开（P2 画布/素材云同步已完成）
```

## 切片作业清单（每次移植照抄）

1. `git fetch origin`；记下上游 commit/tag 与涉及路径。  
2. 新分支：`feat/upstream-<slice-name>`（基于当前 `a-hi1/main`）。  
3. 只改能力相关文件；**不碰** `docker-compose*.yml` / `nginx.conf` / 端口约定，除非切片本身就是部署修复。  
4. 本地验证：未登录 BYOK 生图/画布仍可用；若动云相关再跑 `check-cloud-stack` + `smoke-dual-track`。  
5. 更新：本矩阵状态、`pending-test.mdx`、必要时 `CLAUDE.md`。  
6. `git push a-hi1 <branch>` 或合入 `main` 后推 `a-hi1`。
