## 自用仓库与 Git

| 项 | 约定 |
| --- | --- |
| 推送/部署源 | `https://github.com/a-hi1/infinite-canvas.git` |
| 本机 remote | `a-hi1` → a-hi1/infinite-canvas；`origin` 可能仍是上游 `basketikun/infinite-canvas` |

| 提交范围 | **不要** `git add .`；只 `git add <具体文件>` |

## 部署与端口（三套，勿混）

### 共性

- 主栈：`docker compose -f docker-compose.local.yml` → `app` + `api` + `ai-proxy`
- 容器内 app 听 3000；Nginx 同源 `/api/`、`/ai-proxy/`、可选 `/lan-ai/`
- Nginx **必须** `$http_host` + `X-Forwarded-Host` 保留端口（否则登录 403）
- **禁止被上游覆盖**：compose / nginx / 端口 / 同源 `/api` `/ai-proxy`
- 浏览器代理 ≠ Docker 出网；容器拉 `vidgen.x.ai` 超时可在根 `.env` 设 `HTTP_PROXY`/`HTTPS_PROXY` 后重建 api/ai-proxy；**服务器勿默认照搬本机 789x**

### A. 本机 Windows 开发

- 常同时映射 `3001:3000` + `3011:3000`（以本地 `docker-compose.local.yml` 为准）
- 日常验收优先 `http://127.0.0.1:3011`（避开 VS Code 端口转发抢 3001）
- 可选叠加 `docker-compose.dev-host.yml`
- Vite dev：`/api` `/ai-proxy` 默认代理到 `3011`；可选 `VITE_LAN_AI_TARGET` / `/lan-ai`

```bash
docker compose -f docker-compose.local.yml up -d --build app api
# 硬刷新浏览器
```

### B. 美国/公网服务器（自用）

- 目录：`~/apps/infinite-canvas`
- 端口：`3001:3000`；api 不默认绑宿主机 8080

```bash
cd ~/apps/infinite-canvas
git pull
sudo docker compose -f docker-compose.local.yml up -d --build
sudo docker compose -f docker-compose.local.yml ps
./scripts/check-cloud-stack.sh
# 可选：./scripts/backup-api-data.sh
```

### C. 公司内网 Windows 机（协作演示）

- 路径示例：`D:\wyx_group\project\infinite-canvas`（以用户当前为准）
- **compose 项目名必须** `-p ic3011`，端口 **`3011:3000`**
- 同机常有 :3000 new-api、:3001 旧 infinite-canvas，**禁止抢占**
- 公网/域名访问形态常类似：`http://www.openai2api.com:3011`
- 该机 git remote 常叫 **`origin`** 但指向 a-hi1

**硬约束：不能影响同机其它项目**

- 禁止 Docker engine 重启、禁止 prune、禁止停无关容器
- 禁止改/占 3000、3001（其它服务）
- 只操作 `ic3011` 项目容器

```powershell
cd D:\wyx_group\project\infinite-canvas
git fetch origin
git reset --hard origin/main   # 或 git pull，以该机 remote 名为准
docker compose -p ic3011 -f docker-compose.local.yml up -d --build
docker compose -p ic3011 -f docker-compose.local.yml ps
```

已知部署坑（`846d2ea` 一带已修，部署后须确认镜像含这些）：

- Vite `assetsDir: "static"` + nginx `location = /assets`，避免 SPA `/assets` 刷新 403
- `absolute_redirect off; port_in_redirect off`，避免跳到同域 :3000
- Dockerfile `sed` 去 CRLF，避免 Alpine entrypoint `no such file`
- 资产导入批量 `addAssets` 保序
- 内网 Docker Hub 可能 EOF：可用离线 `docker load`；Windows 注意无 BOM

### /lan-ai 与家里 Grok2API（方案 B）

- 浏览器不要直连 `http://192.168.x.x`（CORS）
- 公网用家里 API：FRP；服务器推荐 `LAN_AI_UPSTREAM=http://infinite-canvas-frps:18000`
- 前端渠道 Base URL：`/lan-ai` + 客户端 API Key
- 家里 Windows frpc 需常开（见 `deploy/lan-tunnel/README.md`）
- 安全：放行 3001、FRP 7000；**不要**对公网放行 18000；勿提交含 token 的 frps/frpc.toml

更短命令见 [ops-daily](/docs/progress/ops-daily)。

### 渠道 / 模型兼容（高频踩坑）

- `compatProfile`：auto / openai / openai-slim / grok-image / relay-fragile
- **视频自定义脚本参数**：`params.seconds` 是 number（例如 `4`），用于 Seedance `/v1/video/generations` 的 `duration`；不要退回字符串 `"4"`
- **原生 API Key Seedance 中转**：OpenAI2API/New API 走 `/v1/video/generations`，`duration:number`；**单图**用 `images[]`；**多图/参考视频**用 `content[]`+`role`（`first_frame`/`last_frame`/`reference_image`/`reference_video`，禁止无 role 的 images 多图）；参考音频仍需火山 Agent Plan。火山 Agent Plan 仍 `/contents/generations/tasks`
- **Grok 图生图**：JSON `POST /images/edits`；有参考图**不再**自动跳 `*-edit`；多参考必须完整 multi-image payload，**禁止静默只发第一张**
- **Grok 视频**：用户当前选择永远优先；禁止硬塞不存在的模型插队；多参考勿退化首图
- **Grok 完成态 URL**：官方形状 `video.url`；`status=done` 时 url 可能空串/晚写——优先读嵌套 `video.url`，完成无地址再等约 3 分钟并试 content 下载，禁止过早当失败
- Sora/Veo：多路径 create/poll；图生禁止无参考文生回退
- Seedance/Agnes 保留；平台视频仍无参考素材服务端路径
- 参考图本地上限 6（平台积分图生图仍最多 4）
- 能力卡：`web/src/lib/model-capability.ts` 只暴露真实可选值

## 工作方式硬约束

- 先理解与建议，**等用户确认再改代码**；未确认不提交、不推送
- **服务器不用助手部署**；只给命令（公司机同样，除非明确授权且只动 `ic3011`）
- 不破坏已实现能力：Grok 多参考、Sora/Veo/Seedance/Agnes、工作台并发/停止、云双轨、画布并发、工作空间既有能力、本地优先
- 动 ai-proxy / 部署 / 端口 / 安全代理时特别谨慎，并同步相关 Markdown
- 未登录 BYOK 必须可用；云失败不阻断本地
- 图生图/多参考：禁止静默只发第一张；禁止擅自把 Grok 模型改回自动 `*-edit`
- 工作空间文件夹：与 `category` 正交，不替代分类墙；智能归类不猜 folder
- 验收优先：`scripts/check-cloud-stack.*`、`scripts/smoke-dual-track.*`；说明仍须人工 UI 的部分
- **本机**改完会影响 Docker 镜像的代码后：**自动** `docker compose -f docker-compose.local.yml up -d --build` 相关服务（app / api / ai-proxy），不要等用户再说「重启」；纯文档可跳过。美国机/公司机仍由用户自部署
- 不要擅自大范围重构
